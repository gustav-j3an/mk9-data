#### Etapa 2: Aplicação Controlada com Stop-Gate em Cada Migration

```bash
migrations=(
  supabase/migrations/20261105165500_m30_harden_industry_active_checkin.sql
  supabase/migrations/20261106131614_m30_serialize_industry_checkin.sql
  supabase/migrations/20261106140000_m37_pending_visit_active_route_guard.sql
  supabase/migrations/20261106150000_m37_checkin_route_and_conflict_guard.sql
  supabase/migrations/20261107140000_m37_reconcile_materialized_pending_recovery.sql
)

for migration in "${migrations[@]}"; do
  mig_basename="$(basename "$migration")"
  expected_ver="$(echo "$mig_basename" | cut -d_ -f1)"
  echo "=========================================================="
  echo ">>> APLICANDO MIGRATION: $mig_basename"
  echo "=========================================================="

  # 1. Copiar migration para o workspace temporário
  cp "$migration" "$WORKDIR/supabase/migrations/"

  # 2. Executar via Supabase CLI com target explícito na homologação
  supabase migration up --remote="$TARGET_PROJECT" --workdir "$WORKDIR"

  # 3. Critério de Interrupção / Verificação de Parada
  #    Conferir via CLI se a versão consta aplicada
  echo ">>> Verificando registro da versão $expected_ver..."
  list_output="$(supabase migration list --remote="$TARGET_PROJECT" --workdir "$WORKDIR")"
  if ! echo "$list_output" | grep -q "$expected_ver"; then
    echo "ERRO FATAL: Migration $mig_basename não foi registrada no ledger remoto!" >&2
    echo "INTERROMPENDO O PROCESSO IMEDIATAMENTE PARA ANÁLISE." >&2
    exit 1
  fi

  echo ">>> Migration $mig_basename aplicada e verificada com sucesso."
done

# Descartar workspace temporário
rm -rf "$WORKDIR"
echo "Aplicação das 5 migrations concluída. Workspace temporário descartado."
```

### 4. Critérios de Interrupção e Tratamento de Falhas Intermediárias

1. **Critérios de Parada Imediata (Stop Gates):**
   - Se qualquer comando `supabase migration up` retornar código de saída diferente de 0.
   - Se o comando `supabase migration list` indicar drift de versões ou versions missing.
   - Se a conectividade de rede for perdida durante a transação.
2. **Tratamento de Falha Intermediária:**
   - **Garantia Transacional das Migrations:** As migrations M30 contêm transactions atômicas implícitas e as migrations M37 contêm blocos explícitos `BEGIN ... COMMIT`. Caso ocorra erro dentro de um arquivo, o PostgreSQL reverte todas as instruções daquela migration.
   - **Isolamento de Estado:** As migrations já aplicadas com sucesso permanecem registradas no ledger. Nenhuma tentativa de reaplicação às cegas deve ser feita.
   - **Procedimento de Análise:** Inspecionar o erro exato no log do CLI, consultar o status das funções no banco e determinar se é caso de ajuste cirúrgico ou acionamento do script de recuperação.

### 5. Limitações de Backup e Plano de Rollback

> [!WARNING]
> **Limitações do Backup em Ambiente Supabase Cloud:**
> - `supabase db dump --remote` depende de Docker Engine local rodando os containers de `pg_dump`. Em ambientes onde o Docker Desktop não está em execução ou o engine não está acessível, dumps completos locais via CLI falham.
> - O Supabase Cloud gerencia snapshots contínuos e backups automáticos (WAL-based / Point-in-Time Recovery no dashboard web). Recomenda-se confirmar a existência do snapshot de segurança no painel do Supabase antes da janela.
> - O dump do schema não inclui configurações globais do Auth (GoTrue) ou Storage S3 buckets.

#### Procedimento de Rollback Estrutural:

1. **Restauração Estrutural das Funções Pré-M30:**
   - Em caso de falha funcional após a aplicação, executar o script DDL canônico [`docs/m37.4-homologation-function-recovery.sql`](file:///c:/projetos/mk9-data/docs/m37.4-homologation-function-recovery.sql).
   - Esse script restaura com fidelidade catalogada as 3 funções operacionais:
     - `public.attendance_check_in`
     - `attendance_private.attendance_start_scheduled_occurrence`

   - Garante a recomposição exata de: `search_path = ''`, `SECURITY DEFINER = true`, owner `postgres` e ACLs (`{postgres=X/postgres,authenticated=X/postgres,...}`).
2. **Objetos que NÃO são revertidos pelo script de recuperação:**
   - O script `docs/m37.4-homologation-function-recovery.sql` reverte **estritamente as três funções afetadas**.
