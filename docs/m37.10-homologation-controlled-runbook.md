### 1. Diagnóstico do Supabase CLI (Versão 3.0.0 Oficial)

O CLI oficial pinado no repositório é a versão `3.0.0` (conforme verificado no pipeline do GitHub Actions). A análise de comandos e parâmetros documentados revela:

#### A. Sintaxe e Comportamento de Comandos:
- **`supabase migration up`**:
  - Aplica migrations locais pendentes ao banco local do projeto.
  - Não oferece parâmetro nativo `--project-ref` ou `--linked` para execução seletiva de uma única migration arbitrária em banco remoto sem aplicar as anteriores.
- **`supabase db push`**:
  - Comando canônico para aplicar migrations locais ao banco remoto vinculado (`--linked`) ou via URL (`--db-url`).
  - Suporta `--dry-run` para inspecionar migrations pendentes sem aplicá-las.
  - Suporta `--include-all` para incluir migrations mesmo com divergência de histórico.
  - **Limitação Crítica**: O `db push` processa em lote todas as migrations locais não registradas. Não possui flag para aplicar somente uma migration específica ignorando versões anteriores ausentes no ledger.
- **Diretiva `[db.migrations] enabled = false` (`supabase/config.toml`)**:
  - Configurada no arquivo canônico do projeto (linhas 60-62).
  - Comportamento documentado: quando `enabled = false`, comandos como `supabase db push` e `supabase db reset` simplesmente **ignoram** a execução de migrations.
  - Qualquer tentativa de rodar `supabase db push` sem alterar explicitamente essa flag resultará em execução nula.
